# 공문 검토·작성 시스템

공공기관 공문·보고서를 **작성**하고 **검토**하는 도구. 웹과 데스크톱 두 가지로 쓸 수 있고,
생성 엔진은 Google Gemini API를 사용한다.

## 구성

```
core/            웹·데스크톱 공용 (여기만 고치면 양쪽에 반영됨)
  prompts.py       문서 3종 × 작성/검토 + 요약·인수인계 프롬프트, 출력 후처리
  orgs.py          기관 정의 로딩·검증
  orgs.json        기본 제공 기관 목록
  gemini.py        Gemini 스트리밍 클라이언트
  store.py         문서·양식 GitHub 보관·조회
  extract.py       hwpx/hwp/docx/pdf/txt(+인수인계용 xlsx/csv/eml) → 텍스트
  hwpx.py          결과 텍스트 → 한글(.hwpx). 서식 원본이 없으면 hwpx_style.py
  hwpx_style.py    사내 보고서 서식(제목 상자·표) 생성기 (kanana-doc 에서 옮김)
  related.py       인수인계 자료와 관련 있는 기관 보관 문서 고르기 (TF-IDF)
api/index.py     웹 백엔드 (FastAPI, Vercel Python 런타임)
public/          웹 프론트엔드 (정적)
desktop/gen.py   데스크톱 앱 (Tkinter)
```

문서 유형은 `공문-외부` / `공문-내부` / `보고서` 3종이며, 각각 작성용·검토용 프롬프트를 가진다.

보고서 양식은 행정안전부의 "AI·사람이 함께 읽는 문서작성" 지침을 반영한다.
머리 부분(제목·일자·부서) 뒤에 요약을 두고, 항목 계층은 `1. → □ → ○`,
표는 단순 구조만, 그림은 관계를 설명하는 문장을 본문에 함께 쓴다.
문체는 한전 관행에 맞춰 명사형 개조식을 유지한다(지침의 서술식은 채택하지 않음).
글꼴·자간·줄간격은 한글 저장 서식(`core/hwpx_style.py`)에서 결정된다. 아래 [저장 (HWPX)] 참고.

## 인수인계 (웹 전용)

전임자의 업무 폴더를 통째로 넣으면 인수인계서 초안을 만든다.
작성 탭의 문서 양식에서 `인수인계서` 를 고르면 입력 칸이 자료 업로드·전임자 메모로 바뀐다.

- 입력: 폴더 선택·파일 선택·끌어다 놓기. 지원 형식 외 파일과 오피스 임시 파일(`~$`)은 자동 제외된다.
  검토 탭 형식에 더해 `.xlsx`(날짜 서식 셀은 날짜로 변환) / `.csv` / `.eml` 을 읽는다.
- 파일은 한 건씩 `/api/extract` 로 추출해 브라우저에 두었다가, 생성 때 `files` 로 한 번에 보낸다.
  파일당 6만 자·전체 60만 자에서 자른다(Vercel 요청 4.5MB 한도).
- 출력: 담당 업무 개요 / 진행 중인 현안 / 연간 업무 달력 / 협의 관계 / 노하우 / 확인 필요 사항 / 참고 자료.
  모든 항목 끝에 `[출처: 파일명]` 이 붙고, 화면의 출처 칩을 누르면 근거 원문과 인용 항목을 볼 수 있다.
  올린 자료에 없는 파일명을 인용하면 빨간 칩(확인 안 됨)으로 표시된다.
- 결과는 `편집` 화면에서 고칠 수 있고, 고친 내용이 미리보기·달력·한글 파일에 반영된다.
- 한글 파일과 `한글 미리보기` 에는 `[출처: …]` 표시를 빼고 넣는다(편집 화면 원문에는 남김 —
  출처 확인 기능이 이 표시를 읽는다). 출처는 문서 끝 `7. 참고 자료` 목록으로만 남는다.
- 연간 업무 달력에 내용이 있으면 한글 파일에서는 `월 | 할 일` 표로 바꿔 넣는다. 한 달에 할 일이
  여럿이면 줄을 나누고 월은 첫 줄에만 쓴다(셀 병합 없는 단순 표). 변환은 `public/index.html` 의
  `handoverExportText` 가 저장·미리보기 직전에 한다.
- 자료에 내용이 없는 섹션·항목은 쓰지 않는다("확인되지 않음", "내용 없음" 같은 줄 금지, 빠진 섹션
  뒤 번호는 당김). 모델이 그래도 쓰면 내보낼 때 그런 줄을 지우고, 본문이 빈 섹션을 빼고 번호를
  다시 매긴다(`dropEmptySections`). 편집 화면 원문은 건드리지 않는다.
- 올린 자료는 생성이 끝나면 `datas/<기관>/인수인계자료/` 에 보관한다(원본 파일명이 제목).
  검토 보관과 같은 품질 게이트(50자 미만·AI 출력물·이미 있는 내용 제외)를 거치고, 파일마다
  커밋하지 않고 Git Data API 로 **한 번에 커밋**한다(`store.save_documents_batch`). 이 폴더는
  작성 탭 양식 참고에는 쓰이지 않고, 다음 인수인계의 기관 보관 문서 후보로만 쓰인다.
- 하루 5회 제한(브라우저 기준)은 작성·검토와 별도로 센다.
- **기관 보관 문서 참고** (항상 켜짐): 같은 기관이 `datas/<기관>/` 에 보관한
  문서(최신 30건, 공문·보고서·인수인계자료 구분 없이)를 읽어 올린 자료와 TF-IDF 유사도가 0.15 이상인 것만 최대 3건
  보조 자료로 붙인다(`core/related.py`). 올린 자료와 사실상 같은 문서(0.9 이상)는 뺀다.
  인용 이름은 `기관보관/유형/본문에서 뽑은 제목` 이고 화면에 파란 칩으로 구분된다.
  프롬프트는 전임자 자료에 나온 업무의 배경·전년 일정·협의 상대를 보완할 때만 쓰게 한다.
  기준값은 실제 보관 문서 44건으로 맞췄다(같은 업무 0.2 안팎, 무관한 문서 0.15 미만).

## 기관

프롬프트에 기관명·본문 자칭·부서명 예시가 주입된다. 웹은 실행 시 기관을 먼저 고르고,
선택 결과를 브라우저에 기억한다. 헤더의 **변경** 버튼으로 언제든 바꿀 수 있다.

기관을 추가하는 방법은 두 가지다.

1. **웹 화면에서 추가** — 기관 선택 창의 `기관 추가`. 기관명만 입력하면 된다.
   배포 없이 즉시 반영되지만 **추가한 브라우저에만 저장**된다.
   다른 사람이나 다른 PC에서는 보이지 않는다.
2. **`core/orgs.json` 편집** — 모두에게 공유되고 영구히 남는다. 약칭·자칭·부서명 예시까지
   지정할 수 있어 결과가 더 정확하다. 데스크톱은 이 방법만 지원한다.

```json
{
  "id": "kogas",
  "name": "한국가스공사",
  "short": "가스공사",
  "alias": "KOGAS",
  "self_ref": "우리 공사",
  "departments_letter": ["전략기획처", "안전관리처"],
  "departments_report": ["생산기술처"]
}
```

`name` 외에는 모두 선택 항목이다. `self_ref` 를 비우면 "우리 기관",
`departments_*` 를 비우면 프롬프트에서 부서명 예시 줄이 빠진다.

기본 목록에는 한국전력공사만 부서명 예시가 채워져 있다. 나머지 기관은 이름·자칭만
등록돼 있으므로, 실제로 쓰려면 해당 기관의 부서명을 채워 넣는 편이 결과가 좋다.

## 웹 — Vercel 배포

1. Vercel 프로젝트를 이 저장소에 연결한다. 프레임워크 프리셋은 **Other**.
2. Settings → Environment Variables 에 `GEMINI_API_KEY` 를 등록한다.
3. Settings → Functions 에서 **Fluid compute** 가 켜져 있는지 확인한다.
   (꺼져 있으면 `vercel.json` 의 `maxDuration: 300` 이 적용되지 않고 60초로 제한된다)
4. 배포.

### 로컬 실행

```bash
pip install -r requirements.txt
export GEMINI_API_KEY=...            # Windows: set GEMINI_API_KEY=...
uvicorn api.index:app --reload --port 8000
```

`http://localhost:8000/api/health` 로 상태를 확인할 수 있다. 정적 페이지는 Vercel이
`public/` 을 루트로 서빙하므로, 로컬에서 UI까지 보려면 `public/index.html` 을 직접 열고
API 주소만 8000번으로 맞추거나 `vercel dev` 를 쓴다.

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 키 설정 여부, 모델 체인, 문서 유형 목록 |
| GET | `/api/orgs` | 기본 제공 기관 목록 |
| GET | `/api/store` | 문서 보관 기능 진단 (토큰·저장소·쓰기 권한) |
| GET·PUT | `/api/format` | 기관·유형별 양식 정의 조회·저장 |
| POST | `/api/extract` | multipart 파일 업로드 → 텍스트 (최대 4MB) |
| POST | `/api/hwpx` | multipart `text` `title` `template?` → `.hwpx` 파일 |
| POST | `/api/generate` | `{task, doc_type, input, org}` → SSE 스트리밍 |

`org` 는 기본 기관이면 id 문자열, 브라우저에 추가한 기관이면 객체를 통째로 보낸다.
서버는 받은 기관 정보를 프롬프트에 넣기 전에 `core/orgs.py` 에서 정규화한다
(제어문자·대괄호 제거, 길이 및 개수 제한).

`/api/generate` 는 `data: {"token": "..."}` 를 반복 전송한 뒤,
마지막에 후처리까지 끝난 전문을 `data: {"done": true, "text": "..."}` 로 보낸다.
클라이언트는 `done` 의 `text` 로 화면을 교체하면 된다.

## 데스크톱

`desktop/run_gemini.vbs` 실행. API 키는 다음 순서로 찾는다.

1. 환경변수 `GEMINI_API_KEY`
2. `desktop/gemini_key.txt`
3. 둘 다 없으면 입력 창이 뜨고, 입력한 키를 2번 파일에 저장

백엔드는 `SLM_BACKEND` 로 고정할 수 있다 (`gemini` | `api` | `onnx`).
미지정 시 키가 있으면 gemini, `SLM_API_URL` 이 있으면 api, 아니면 로컬 onnx 를 쓴다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | — | **필수** (`GEMINI_KEY` 도 인식) |

| `GEMINI_TEMPERATURE` | `0.3` | 양식 준수가 중요해 낮게 잡음 |
| `GEMINI_TOP_P` | `0.9` | |
| `GEMINI_TOP_K` | `0` | 0이면 미사용 |
| `GEMINI_MAX_OUTPUT_TOKENS` | `4096` | 문서가 잘리면 올린다 |

| `SLM_API_URL` | — | 데스크톱 `api` 백엔드용 |

## 모델 폴백

무료 티어 할당량이 소진되거나 모델이 과부하일 때 다음 모델로 자동 전환한다.
기본 체인은 `core/gemini.py` 의 `DEFAULT_MODEL_CHAIN`:

```
gemini-3.7-flash → 3.6-flash → 3.5-flash → 2.5-flash → 3.1-pro-preview → flash-lite 계열
```

Flash 를 앞에 둔다. Pro 를 1순위로 두었을 때 생성이 몇 배 느리고 thinking 을 끌 수 없어
(`GEMINI_THINKING_BUDGET=0` 이 적용되지 않음) 인수인계처럼 큰 작업은 수 분씩 걸렸다.
Pro 는 Flash 가 모두 막혔을 때 쓰는 예비다. 다시 Pro 를 앞에 두려면 코드 대신
환경 변수 `GEMINI_MODEL=gemini-3.1-pro-preview` 로 선두만 바꾸면 된다.

- 전환 대상: `404`(모델 없음), `429`(할당량), `500/502/503/504`(과부하),
  그리고 "not found / not supported" 류 메시지를 가진 `400`
- 즉시 실패: `401`/`403`(키 문제 — 모델을 바꿔도 동일), 그 외 `400`(요청 자체가 잘못됨)
- **이미 토큰을 내보낸 뒤에는 전환하지 않는다.** 전환하면 앞부분이 중복 출력되므로,
  이 경우엔 오류로 처리한다.
- 존재하지 않는 모델 ID가 체인에 섞여 있어도 404로 건너뛰므로 안전하다.
  404 를 받은 모델은 그 서버 프로세스가 살아 있는 동안 기억해 다시 시도하지 않는다
  (요청마다 큰 입력을 헛보내며 404 를 맞는 시간을 없앤다).
  실제 사용 가능한 목록은 `GET /v1beta/models` 로 확인할 수 있고,
  데스크톱은 시작 시 이 목록으로 체인을 한 번 걸러낸다.

## 문서 보관과 참고

검토를 실행하면 **사용자가 올린 원문**이 자동으로 이 저장소에 보관되고, 이후
**같은 기관 · 같은 유형**의 문서를 작성·검토할 때 참고 자료로 쓰인다.

```
datas/<기관 id>/<문서 유형>/
    양식.md                       ← 이 기관이 정한 양식 (선택)
    <YYYYMMDD-HHMMSS>-<제목>.txt  ← 실제 사용된 문서
```

- 보관 대상은 **AI 가 만든 수정본이 아니라 업로드한 원문**이다.
  실제 기관에서 쓰인 문서라야 참고 예시로 신뢰할 수 있다.
  AI 출력물을 다시 예시로 넣으면 오류가 누적된다.
- 50자 미만이면 저장하지 않는다.
- 작성 시에는 **요청 내용과 관련 있는 문서**를 최대 3건, 문서당 2,500자까지 덧붙인다
  (`MAX_REFERENCES`, `MAX_REFERENCE_CHARS`). 후보는 그 기관의 보관 문서 최신 30건이며
  유형을 가리지 않고 `인수인계자료` 도 포함한다. 고르는 방식은 인수인계와 같은 TF-IDF
  (`core/related.py`)이되, 입력이 짧으므로 기준을 따로 둔다: 유사도 0.09 이상이면서
  의미 있는 낱말이 2개 이상 겹칠 때만 관련 문서로 본다("개최·운영·현황" 같은 상투어 제외).
  실제 보관 문서로 확인한 값이다(관련 0.13~0.42, 무관 0.07 이하).
- 관련 문서는 같은 유형이면 양식·문체를 따르고, 배경·기관명·전년 일정처럼 요청과 직접
  관련된 사실은 참고할 수 있다. 요청하지 않은 사업·수치·일정은 끌어오지 않게 지시한다.
- 관련 문서가 없으면 예전처럼 같은 유형의 최근 문서를 양식·문체 참고로만 붙인다.
  완료 상태줄에 `관련 문서 N건 참고: 제목…` 또는 `양식 참고 문서 N건 반영` 이 표시된다.
- 한계: 낱말 단위로 비교하므로 띄어쓰기가 크게 다르면("사회적가치 창출 협의체" ↔
  "사회적가치창출협의체") 관련 문서를 놓칠 수 있다.
- 보관에 실패해도 검토 결과는 정상적으로 표시된다.

### 기관별 양식 정의 (`양식.md`)

양식은 법정 표준이 아니라 기관마다 다른 관행이므로, 코드에 하드코딩하지 않고
기관·유형별로 정의할 수 있게 했다. 해당 경로에 `양식.md` 를 두면 그 내용이
프롬프트에 들어가고, **코드에 있는 기본 양식보다 우선한다.**

우선순위는 `양식.md` > `datas/` 의 실제 문서 > 코드의 기본 규칙 순이다.

`datas/` 는 GitHub API 로 매 요청마다 읽으므로 **양식을 고치면 재배포 없이
다음 요청부터 바로 반영된다.** 편집 방법은 두 가지다.

- GitHub 에서 파일을 직접 수정
- `PUT /api/format` — `{doc_type, org, text}`
  (`GET /api/format?doc_type=보고서&org=kepco` 로 현재 내용 확인)

내용은 자유 형식 마크다운이다. 예:

```markdown
# 보고서 양식

## 머리 부분
- 첫 줄: 문서 제목
- 제목 바로 아래 오른쪽에 일자, 그 아래 부서

## 항목 기호
- 1. 2. 3. → □ → ○
- "가. 나." 는 쓰지 않음
```

작성·검토 결과 상태줄에 "기관 양식 적용" 이 뜨면 반영된 것이다.
데스크톱은 저장소를 읽지 않으므로 코드의 기본 양식만 사용한다.

### 설정

서버리스에는 쓸 수 있는 파일 시스템이 없어 GitHub Contents API 로 직접 커밋한다.
Vercel 환경 변수에 다음을 등록해야 기능이 켜진다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GITHUB_TOKEN` | — | 이 저장소 `contents: write` 권한 (`GH_TOKEN` 도 인식) |
| `GITHUB_REPO` | (없음, 보관 기능을 쓰려면 필수) | `owner/repo` |
| `GITHUB_BRANCH` | `main` | |

토큰이 없으면 보관·참고 기능만 꺼지고 나머지는 그대로 동작한다.
`/api/health` 의 `store_enabled` 로 확인할 수 있다.

### 재배포 방지

문서를 저장할 때마다 커밋이 생기면 Vercel 이 매번 재배포된다. 이를 막기 위해
보관 커밋 메시지에 `[skip deploy]` 를 넣고, `vercel.json` 의 `ignoreCommand` 가
그 표식이 있는 커밋의 빌드를 건너뛴다. Vercel 은 `[skip ci]` 를 기본 지원하지 않으므로
이 설정이 반드시 있어야 한다.

> **주의** — 사내 문서가 저장소에 영구 보관된다. 저장소를 반드시 비공개로 유지할 것.
> 이전에는 `.gitignore` 로 `datas/` 를 제외해 문서를 저장소에 두지 않았으나,
> 이 기능을 위해 해제했다.

## 저장 (HWPX)

결과는 한글 문서(`.hwpx`)로만 저장한다. 웹은 항상 **사내 보고서 서식**으로 만든다
(`core/hwpx_style.py`, kanana-doc 에서 한글로 열어 맞춘 구성을 그대로 옮김).

| 요소 | 서식 |
|---|---|
| 제목(첫 줄) | 1칸 표 상자, 옅은 회색 바탕, 오른쪽·아래 굵은 테두리(그림자), HY헤드라인M 22pt |
| 일자·부서 | 제목 바로 밑 오른쪽 정렬 (일자 줄, 또는 공백 16칸 이상으로 민 줄) |
| 소제목 `1. 추진 배경` | HY헤드라인M 17pt, 위 여백으로 간격 (빈 줄은 버림) |
| 본문 `□ ○` | 휴먼명조 15pt, 자간 -5%, 줄간격 180%, □ 1칸·○ 3칸 들여쓰기 |
| 표 `\| 칸 \| 칸 \|` | 두 줄 이상 이어지면 한글 표. 첫 줄 머리글(굵게·회색), 휴먼명조 12pt. 칸 너비는 칸의 가장 긴 글자 수(4~30자로 제한)에 비례해 본문 폭을 나누고, 14자 넘는 글이 든 칸은 왼쪽 정렬 |
| 쪽 | A4 세로, 여백 위아래 10mm·좌우 18mm |

- 공문(첫 줄이 `수신`·`제목`·`내부결재`)은 제목 상자·소제목 서식 없이 본문 글자 그대로 쓴다. 표는 똑같이 바뀐다.
- 글꼴·크기·여백은 `core/hwpx_style.py` 맨 위 설정값만 고치면 된다. 글꼴·여백을 바꾸면
  `core/prompts.py` 의 `LINE_CHARS`(한 줄 36자)·`TITLE_CHARS`(제목 20자)도 맞출 것.
- 작성 프롬프트에는 표 쓰는 법(`TABLE_NOTE`)과 한 줄 길이(`LINE_NOTE`)가 붙는다. 수량·일정·예산처럼
  나란히 비교하는 내용만 표로 쓰게 한다.
- 화면의 작성 결과와 인수인계 `한글 미리보기` 는 같은 규칙으로 그린 미리보기다
  (`public/index.html` 의 `renderDoc` — 저장 서식을 바꾸면 함께 고칠 것).

데스크톱 앱은 불러온 `.hwpx` 를 서식 원본으로 넘길 수 있다(`build_hwpx(template=...)`).
이때는 원본의 글꼴·여백을 물려받고 본문만 교체하며, 표는 글자 그대로 남는다.
`core/hwpx_template.hwpx` 를 두면 웹에서도 그 파일이 서식 원본이 된다.

`mimetype` 항목은 ZIP 의 첫 엔트리이면서 무압축(STORED)이어야 한다(ODF/EPUB 와 같은 규약).
이 조건을 어기면 한글이 파일을 인식하지 못한다.

## 알려진 제약

- **구형 `.hwp`** — `olefile` 로 본문 텍스트를 직접 추출해 지원한다(순수 파이썬).
  표·그림·서식은 버리고 문단 텍스트만 얻는다(검토용). 암호가 걸린 파일은 열 수 없다.
- **업로드 4MB** — Vercel 요청 본문 상한(4.5MB)보다 낮게 잡은 값.
- **HWPX 직접 생성은 미검증** — 위 2번 방식은 실제 한글에서 열어 확인하지 못했다.
  열기에 실패하면 1번 템플릿 방식으로 전환하면 해결된다.
- **표·이미지 미지원** — 저장되는 것은 문단 텍스트뿐이다. 서식은 한글에서 조정해야 한다.
